## [v0.7.9] - 2026-08-02

### 改动意图
* 为真实环境下的音频解析做 prework：本版本先建立仅依赖 `mode`、`sample_rate_hz` 和标准时序的无干扰整段解析契约，再逐步加入载波/符号同步、频偏估计、采样时钟恢复、软判决和实时解码。

### 关联版本
* Android：`v0.6.2`
* Web：`2026-08-02`

### 新增功能 (Added)
* 增加 `mini` 无 metadata clean decode：当 `frame_samples=0` 时，decoder 会从 PCM 的 tone/silence run 自动估计 Morse unit，并覆盖不同 WPM unit 的整段解码。
* 增加 `ultra` 双速率自动 decode：当 `mode=ultra`、`sample_rate_hz` 已知且 `frame_samples=0` 时，decoder 会分别尝试 `15.625 Bd` 和 `31.25 Bd` 的标准符号边界。
* 增加 `flash` 无 metadata clean decode：当 `mode=flash`、`sample_rate_hz` 已知且 `frame_samples=0` 时，decoder 会按当前 20 frames/s 时序，并枚举 6 组标准 signal/voicing 风格自动解析整段 PCM。

### 技术改进/重构 (Changed/Refactor)
* 调整 `mini` 与 `ultra` 的 clean decode 契约，把 `frame_samples=0` 明确为 decoder-only 自动时序 sentinel；生成侧仍必须提供明确的 frame/symbol 时序。
* 调整 `ultra` 自动候选的接受条件，使用 preamble、tail、FEC、Varicode 和完整文本回编码校验筛选唯一结果，并按最终解析出的 symbol unit 构建 follow 数据。
* 调整 `flash` 自动候选的接受条件：由于 Flash 没有 frame length、sync 或 CRC 字段，使用解码字节对应的文本和 signal/voicing 风格精确回生 PCM 校验，并且只接受唯一候选。
* 明确两种模式的当前边界：自动解析面向已知 `sample_rate_hz`、从首个符号边界开始的整段无干扰 PCM；尚未包含载波/符号同步、频偏估计、采样时钟恢复、软判决或实时增量解码。

### 修复 (Fixed)
* 修复 `ultra` 在缺少 frame metadata 时默认固定按单一速率解析的问题，使无干扰的 `15.625 Bd` 与 `31.25 Bd` 音频都能通过 `mode=ultra` 和实际采样率自动选择正确的符号边界。
* 修复 `flash` 缺少 frame metadata 时无法解析的问题，使标准、hostility、litany、collapse、zeal 和 void 风格的无干扰生成 PCM 可仅依赖 `mode=flash` 与 `sample_rate_hz` 解析，并拒绝被修改的 PCM。
